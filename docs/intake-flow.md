# Google フォームでコンテンツを集めてサイトを生成する

企業に Google フォームで文章と画像を入力してもらい、その回答から
`src/config/site.config.ts` を自動生成して3サイトをビルドする運用です。

```
Google フォーム 2枚            回答スプレッドシート        このリポジトリ
┌──────────────────┐         ┌─────────────────┐        ┌──────────────────────┐
│ A 会社基本情報   │ ──────▶ │ フォームの回答 1 │ ──CSV─▶│ intake/company.csv   │
│   （1回だけ）    │         │                  │        │                      │
├──────────────────┤         ├─────────────────┤        ├──────────────────────┤
│ B コンテンツ登録 │ ──────▶ │ フォームの回答 2 │ ──CSV─▶│ intake/content.csv   │
│   （何件でも）   │         │                  │        └──────────┬───────────┘
└──────────────────┘         └─────────────────┘                   │
                                                    npm run intake:build
                                                                   ▼
                                                    src/config/site.config.ts
                                                                   │
                                                          npm run build
                                                                   ▼
                                                  dist-jobs / dist-people / dist-faq
```

質問文は `scripts/intake/fields.mjs` に定義されており、
フォーム・CSVひな形・変換スクリプトの3つがすべてそこから作られます。
**質問文が回答シートの列見出しになる**ため、定義とフォームは常に一致します。

## 手順

### 1. フォームを作る（初回のみ）

```bash
npm run intake:form      # intake/create-forms.gs を生成
```

1. [script.google.com](https://script.google.com/) で新しいプロジェクトを作る
2. `intake/create-forms.gs` の中身をすべて貼り付ける
3. 関数 `createForms` を実行する（初回は権限の承認を求められます）
4. 実行ログにフォーム2つと回答スプレッドシートのURLが出力されます

フォームAは7セクション71問、フォームBは種別で分岐して28問です。
どちらも「回答後の編集」を許可してあるので、送信後に回答者自身が修正できます。

> **質問文はフォーム画面で編集しないでください。**
> 列見出しが変わり `npm run intake:build` が読めなくなります。
> 文言を変えたい場合は `scripts/intake/fields.mjs` の `q` を直して `npm run intake:form` からやり直してください。

### 2. 企業に入力してもらう

| フォーム | 提出回数 | 内容 |
|----------|----------|------|
| A 会社基本情報 | 1社1回 | 社名・PURPOSE・配色・3ページ分の見出しとリード・数字・バリュー・キャリアパス・選考フロー・募集要項 |
| B コンテンツ登録 | 1件ごと | 事業 / 職種 / 社員インタビュー / 社員（小カード）/ よくある質問 |

フォームBは「登録する内容」で入力欄が切り替わります。
事業3件・職種4件・社員2名なら計9回送信してもらう形です。
「表示順」に数字を入れると並び順を指定できます（空欄なら送信順）。

各項目の内容と補足文の一覧は [`intake/fields.md`](../intake/fields.md) にあります。
記入済みの例は [`intake/sample/`](../intake/sample/) に置いてあります。

### 3. 回答をCSVで取り出す

回答スプレッドシートで、タブごとに
**ファイル → ダウンロード → カンマ区切り形式（.csv）** を実行し、次の名前で保存します。

| スプレッドシートのタブ | 保存先 |
|------------------------|--------|
| フォームの回答 1（会社基本情報） | `intake/company.csv` |
| フォームの回答 2（コンテンツ登録） | `intake/content.csv` |

タイムスタンプやメールアドレスなど余分な列が含まれていても無視されます。

### 4. 画像を配置する

画像の質問は既定では**記述式**（公開URL または ファイル名）です。

- **公開URLを入力してもらった場合** — そのままサイトから参照されます。設置作業は不要です
- **ファイル名を入力してもらった場合** — 別途受け取った画像を `public/images/` に同じ名前で置きます
- **フォームを「ファイルのアップロード」に変えた場合** — 回答には Google ドライブのURLが入ります。
  `npm run intake:build` が `intake/image-manifest.md` に
  「どのファイルを `public/images/` の何という名前で保存するか」の一覧を書き出すので、それに従って配置します

推奨サイズは [`docs/images.md`](images.md) を参照してください。

### 5. 設定を生成してビルドする

```bash
npm run intake:build     # intake/*.csv → src/config/site.config.ts
npm run dev              # 確認
npm run build            # dist-jobs / dist-people / dist-faq を出力
```

`intake:build` は次を自動で補います（フォームで聞かない項目）。

- 通し番号（`01` `02` …）、事業・職種・社員のアクセント色（登録順に巡回）
- セクションの英字ラベル（`01 — Business` など）、`A DAY IN THE LIFE`、`Q.` `A.` などの微細ラベル
- ボタンのホバー色とタグの淡色（メインカラーから自動計算）
- 比較表の列（職種の登録順・名前をそのまま使用）
- FAQのカテゴリまとめ（同じカテゴリ名の質問がひとまとまりになる）

**中身が1件も無いセクションは出力されません。** 事業を1件も登録しなければ事業セクションごと消え、
比較表の行を書かなければ比較表が消えます。

生成された `site.config.ts` は普通のTypeScriptファイルなので、
そのまま手で微調整してかまいません（次回の `intake:build` で上書きされる点にだけ注意）。

## エラーと警告

`intake:build` は次を検出します。

| 種類 | 例 | 挙動 |
|------|-----|------|
| エラー | 必須項目が空 / 「登録する内容」が不明な値 | 生成せず終了（該当行と質問名を表示） |
| 警告 | 画像が未入力 / 比較表の値の数が職種数と合わない / メインカラーが16進数でない | 既定値で続行 |
| 列不足 | CSVに定義どおりの列見出しが無い | 見つからなかった質問名を一覧表示 |

## Google フォームを使わない場合

同じCSVを直接埋めても動きます。

```bash
npm run intake:template          # intake/company.csv と content.csv のひな形（見出し行のみ）を生成
```

見出し行はフォームの質問文と同一なので、スプレッドシートで配って
記入してもらい、CSVで受け取る運用も可能です。
長文の項目は改行を含むため、Excelよりスプレッドシートを推奨します。

## 項目を増やしたいとき

1. `scripts/intake/fields.mjs` に項目を追加する（`q` が質問文、`path` が設定の書き込み先）
2. 必要なら `src/config/schema.ts` に型を足す
3. `npm run intake:form` と `npm run intake:template` を実行し直す
4. フォームを作り直す（既存フォームには反映されません）

## 注意点

- **回答CSVには氏名などの個人情報が含まれます。** リポジトリにコミットする運用にするなら、
  `intake/*.csv` を `.gitignore` に入れるか、公開リポジトリを避けてください
- **フォームAを2回以上提出した場合**、`intake:build` は最後の行（最新の回答）を使います
- 現状は **CSVを手でダウンロードする** 運用です。Apps Script から GitHub API を叩いて
  自動コミットさせれば「フォーム送信 → 自動デプロイ」まで繋げられますが、
  トークン管理が必要になるため既定では組み込んでいません
